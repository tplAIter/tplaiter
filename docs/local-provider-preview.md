# Installed local provider preview

The `context preview-catalog` and `context preview-resource` CLI actions and the existing MCP `context` tool read an operator-selected, prestarted local provider. Results are explicitly **local-untrusted-observed**. Source and publisher authentication and organization admission are `none`; kernel account observations do not authenticate the serving program. This route does not complete full C02, E07 or authenticated external context routing.

The provider uses the existing `local-provider.session/v1` NDJSON contract. Core does not launch a provider, load its code, execute resources or tools, read credentials, or accept endpoint paths from an installed request. Initial support is Darwin Unix sockets; unsupported platforms refuse this route while native operations retain their existing contracts.

## Operator installation

Use the real build-time `tplaiter-oss-register --local-providers <operator-input.json> --project-contexts <contexts.json> --root <fresh-install-root>` command. The operator input is at most eight closed specs with `registrationID`, `projectKeys`, `protocol: "local-provider.session/v1"`, `qualification: "local-untrusted-observed"`, `endpoint` (`kind: "unix"`, absolute `socketPath`, numeric `ownerUID`), and `limits` (`frameBytes`, `totalBytes`, `pages`, `sourceBytes`, `deadlineMs`). The generator assigns `installationID`, writes confined immutable registration documents, generates runtime-install/v2 and returns the actual registration path/digest for the existing installed binary linker boundary. Pin those generated values through the normal source-build installation mechanism. Run the installed binary's `trust provision` before use.

This input is build-time operator selection, never runtime connection authority. Keep machine-specific endpoint/config files outside public repositories. Start and maintain the service separately in a physical operator-owned 0700 socket directory. Core never creates, unlinks or starts it. Changing a requested host selection on reuse refuses; use a fresh installation for an explicitly changed registration. No local input preserves runtime-install/v1 generation and digest semantics. Native v1 stays dependency-free and organization loading still refuses its unavailable protected backend.

Installation pins establish which registration was selected. No-follow directory/endpoint checks and Darwin kernel UID/PID observations constrain the selected local namespace/account. Code identity remains `unchecked`. Same-account transient endpoint impersonation/replacement is not cryptographically excluded; pathname checks and UID are not code authentication or protected organization authority.

## Read-only requests

CLI discovery: `tplaiter context preview-catalog --registration <installed-id> --json`.

The MCP `context` tool takes `action: "preview-catalog"` and `preview: {"registrationID": "<installed-id>"}`. Native actions retain the existing `request` object; local actions require `preview` and reject mixing the two. Project-context and directory selectors still select only installed project contexts.

Discovery exposes captured `assets` with the exact source/asset IDs and separate preview resource URIs. Asset pins and byte lengths declare expected content; they do not assert that a body was already read. Use `preview-resource` with `registrationID`, `sourceID`, `assetID`, optional `required`, bounds and optional `expectedCatalogSHA256`. Bodies come from immutable same-connection content receipts. They are byte observations relative to producer-declared pins, not independent upstream authenticity.

The distinct MCP template `tplaiter://context-preview/{projectContext}/{registrationID}/{catalogSHA256}/{sourceID}/{assetID}` performs fresh installed selection, catalog reconstruction and pinned reads. The signed native `tplaiter://context/` resource route remains separate. Changed catalog pins refuse stale. A one-connection producer must be prestarted for each invocation; core does not invent a persistent daemon. Fresh resource actions obtain catalog and bodies on one connection. There is no preview continuation/cross-session producer cursor.

## Data and bounds

`ContextData.localPreview` is the new typed local result. `ContextData.packet`, source-authentication evidence, C03 excerpts, C04 spending and authenticated snapshots are absent. Local metadata uses the existing anonymous selector and complete required/dependency floor. Optional diagnostic catalog bytes and resource bodies are base64 so JSON envelope serialization cannot normalize their pinned bytes. Selected metadata is a declared view, never raw receipt proof. Provider-authored source, evidence, origin, mode and ownership strings remain untrusted declarations. A digest match proves observed byte consistency, not publisher/source truth.

Catalog mode returns bounded selected metadata and its complete mandatory floor, with read IDs only for selected resource records. The full exact catalog remains captured and pin-validated internally; `observation.catalogSHA256` and `catalogByteLength` describe that complete receipt. `catalogWire` is absent by default. Request `includeCatalogWire: true` explicitly for diagnostic base64 receipt bytes; the whole diagnostic must fit the complete successful envelope or the action refuses without truncation. Resource mode includes the complete declared metadata floor and every mandatory static resource body; unresolved, unavailable, ambiguous or oversized mandatory content refuses without partial output. UTF-8 conversion never replaces binary bytes. Wire frames/total/pages/read limits and the complete serialized successful CLI/MCP envelopes have independent finite bounds. MCP accounting includes its actual correlation ID and resource/tool wrapper. Oversized success is replaced with a typed refusal, never a truncated floor. Typed refusals themselves are not promised to fit an arbitrarily tiny requested success budget.

The maximum complete successful delivery is 32768 bytes. The producer's source-byte ceiling is at most 8192 and deadline at most 2000 ms; tighter installed/caller ceilings win. Cancellation closes the connection. Registration/namespace observations are rechecked before output. No model is called and token/window capacity stays unknown.

Public tests use independently authored synthetic data and the actual operator command, installation pins, provisioning and installed CLI/MCP. Private counterpart invocation records, raw outputs and content stay outside public Git. These proofs establish qualified local interoperability; normal dependency enrollment, organization read leases and full 9.1 remain separate work.

## Context-efficiency amendment

The original design and first implementation freeze required whole-catalog delivery. The approved amendment makes it an explicit diagnostic only: normal sparse retrieval retains the complete internal receipt but delivers selected metadata, the mandatory floor and requested floor bodies. This preserves exact pin validation without duplicating the whole catalog in model context. Large synthetic installed tests cover sparse success and missing/overbudget floor and diagnostic refusal.

## Identifier grammar and schema limits

Local registration IDs and referenced project keys retain the existing host token grammar: nonempty valid UTF-8, excluding only NUL, TAB, CR, LF, ASCII space, slash and backslash. Form feed, vertical tab and non-ASCII whitespace are permitted; do not interpret `\s` as this contract. Local registration IDs and project keys are limited to 64 UTF-8 bytes by admission. JSON Schema `maxLength` counts Unicode code points and cannot by itself assert that byte limit: 33 copies of a two-byte character satisfy the 64-code-point scalar shape but fail installed admission. The schema's explicit exclusion and `not` rule also refuse trailing forbidden line breaks independently of regular-expression end-anchor behavior.

Global runtime project-context keys retain their existing token grammar without a 64-byte cap; only a key referenced by a local registration gets the local byte cap. The existing operator writer has its separate project-enrollment grammar (ASCII letters/digits and `-_.:`, up to 256 bytes). That writer guard is unchanged; a permissive runtime token is not a claim that every enrollment writer can produce it. The on-demand reflected request schema describes structural inputs; `NormalizeLocalPreview` and freshly pinned host selection enforce the additional lexical/UTF-8 byte guards before any connection. Neither a schema match nor an identifier label is authority. Preview response selection identifiers use the same explicit token exclusions as their pinned registration source.
