# Optional local provider operations

The public provider client can describe, inspect, resolve and observe source containment through its existing host-owned `local-provider.session/v1` connection. Catalog reconstruction and pinned reads keep their existing APIs. `Open` still requires only its existing catalog/read operations; optional support is checked when a method is called. Missing support returns `SESSION_OPERATION_UNSUPPORTED` without sending a frame or closing the session.

`Describe` must match the captured negotiation description. `Inspect` and `Resolve` accept only captured source/asset IDs and send the captured immutable commit. Returned descriptors must match exactly; resolve never looks up a moving branch or performs a fetch. `Graph` accepts the complete captured source-to-asset containment relation with exact anchors, no foreign or duplicate endpoints, and explicit unresolved layer descriptions. It refuses source-narrowed sessions because this wire operation cannot narrow its result. It does not implement a semantic, export, workflow or package graph engine.

Each successful method returns an immutable `OperationReceipt` with copied bytes, the operation name and copied binding. Receipt bytes retain the peer representation. Zero receipts provide no evidence. These are local observations relative to the captured peer declarations, not source authentication, publisher identity, installed code identity, permissions or organization admission. `RequireProduction` continues to refuse.

Methods reuse the existing frame/aggregate-byte/deadline limits, cancellation and single-flight guard. Invalid identities, malformed responses and transport failures close the owned session; invalid selectors and unsupported optional operations send nothing. The client accepts no command, shell, executable path, endpoint, root, reader callback or caller trust flag and never starts a provider. The new focused test uses independently authored neutral peers; it is not installed interoperability evidence.
