# Root-rule data preparation

`exports.PrepareRootRules(ctx, source, pin)` consumes a `deps.VerifiedSource` from the actual stable runtime's `SourceReader`. `AcceptedPin()` retains a deep copy of the exact pin accepted after all reader checks. Nil/zero sources have no accepted pin. The producer compares the supplied immutable source record with that retained pin before deriving anything. Provider and requested-ref remain routing/provenance labels; statement CAS, source, contract, entries and content remain separately bound facts. This API grants no writer, native lifecycle, organization admission or executable action authority.

`tplaiter.dev/root-rule/v1` is a new deterministic **data identity** domain, distinct from modifier composition-input and raw file/content/statement hashes. Each rule digest hashes the domain framing and canonical complete closure plus kind and complete original record. The closure includes the full accepted pin, subject, ordered source entries, canonical native manifest, exact manifest/contract bytes and exact source-local index. IDs are `root.file.<64 hex>`, `root.generator.<64 hex>` and `root.export.<64 hex>` derived from the complete canonical original record; collisions refuse.

The producer owns every regular engine-root file's original source entry and output mapping (the existing gotemplate `.tmpl` suffix rule), every complete original generator object with all targets/parameters/conditions/anchors plus retained snippet/insert resources, and every explicitly indexed export payload and parsed block descriptor. Anchor routing must refer to a real root output and exactly one anchor occurrence. Generator resources must have exactly one complete authored export mapping. Payload file modes/hashes/target mappings, block descriptors/bodies and package slot values must match retained source bytes. Unknown export mappings, omitted payloads, conflicting output targets, duplicate identities, unsafe/missing resources and unsupported manifest sections refuse the **whole** result. Conditional/settings/migrations/hooks/tool-execution sections need separate interpretation; they are not silently projected as unconditional ownership.

## Authored export metadata

`exports/catalog.source.json` uses `tplaiter.dev/source-local-export-index/v1`. It is **not** an installed catalog. Its closed records contain only id, domain, name, strict-semver version, contentDigest, requires, parameters and toolDigest. No source/provider/node-key/authority field is permitted. The parser bounds raw bytes to64KiB and entries to256, rejects duplicate JSON keys, unknown/missing fields, unsorted/duplicate identities and malformed scalar/version/digest/selector fields. It closes against every direct `exports/*.payload.json`; unknown files under that namespace or missing indexed payloads refuse. Current root preparation refuses nonempty export parameters/requirements until their ownership mappings are implemented. The schema describes data shape; canonical integer spelling, byte limits and whole-source/mapping constraints are additionally enforced by the parser/producer.

React's new seven-record index assigns **new authored metadata** version `1.0.0-preview.1`: router/UI are block-domain entries, skills is skill-domain, and data/packages/SPA-build/generator-routing are package-domain entries. These assignments are not inferred from or attributed to historical React `fd881a92`. `toolDigest` binds the exact retained genuine Bun lock bytes; it is dependency data, not a tool execution permit. Payload IDs and bodies are unchanged except the newly authored complete generator-resource payload. All85 historical React leaves stay byte/mode identical. Publication creates a new source subject R; its evidence must be obtained through the normal operator bundle route before full positive preparation is claimed.

`ProjectRootCatalog` re-derives the preparation from its retained opaque source, rejects mutated index/pin/closure data, and compares the supplied source node against the source graph derived from the accepted pin before binding the existing catalog source/provider fields. It is a data projection, not source admission; the source node itself is not authenticated by this function. Never label an arbitrary caller-created graph as admitted.

## Descriptor and lifecycle limits

After real R capture, predecessor operations must retire exact original SPA index/main/router/pages/tests, old build surfaces and original generator routing using the newly computed original rule digests. Package changes need explicit slot-aware replacement and preservation of reusable dependency/source files; deleting all package or reusable modules is not acceptable. Next selfSource refers to earlier immutable Next content C, avoiding descriptor recursion. New composition, conversion, updates and reversal still require actual native ownership/writer integration and installed proofs. An add-only descriptor is not full React-to-Next conversion.
