# Complete ROOT context wire v2

The installed `context select` CLI and MCP `context` action `select` return
`tplaiter.dev/context-root-selection/v2` bodies. Selection requests, native source
contracts and empty-dependency guards retain their existing versions. The route
uses the actual installed source admission and read lease through final complete
serialized delivery. It grants no model capacity, tool execution, organization
authority or project mutation.

All named file images remain complete base64 bytes with source/target paths,
mode, content hash and complete selected-export identity. Decode these images
before following their plain English procedures and required document links.
They are task context; selecting a skill does not install or execute it.

## Lossless C03 facts

The body packet is `tplaiter.dev/context-index-facts/v2`. The compiled
`contextindex.DecodeRootFactsV2` API, also used by `resultdto.RootContextBody` JSON
decoding, reconstructs the complete original C03 v1 packet. No consumer needs to
invent an interpreter or resolve an external pointer.

`descriptorDefaults` shares identical sourceId, mode, ownership, executor,
inputs, updateTriggers, requires, produces and quality fields. Records retain
id, kind, line, state and descriptor version/sourcePath/contentSHA256. Optional
exportRef indexes the complete typed ExportEntry table. An optional per-record
mode overrides the shared mode, preserving supported 100644/100755 mixed images. Descriptor id/kind are
restored from the record. Record itemId/name equal id, path equals sourcePath,
and sourceId equals the descriptor's sourceId. Encoding refuses any violation
of these explicit ROOT equalities.

Relations retain their ordered endpoints and reference complete
kind/attributes/provenance facts. Sharing facts does not coalesce records,
relations, exports, dependency chains or image identities. The remaining packet
members retain full source anchors/pins, requiredFloor IDs, sourceEvidence,
excerpts, externalReferences, graphDigest and match counts.

`logicalSHA256` hashes canonical complete logical C03 JSON. The restored packet's
`bytes` remains its original ordinary typed JSON length, including that field.
Decoding verifies the digest, logical size, complete floor, excerpt associations,
references and deterministic tables. Missing, unknown and duplicate keys or
unused/duplicate table entries refuse. Existing source/export/graph digest
preimages are unchanged. Fact data alone never authenticates a source.

Ordinary query/local-preview output and C04 v1 selection wire/fingerprints are
unchanged. ROOT v2 projection derives from an owned authenticated C03 selection;
its original logical bytes and concrete bindings remain the freshness floor.
No caller packet, permission Boolean or replacement binding constructs it.

## Complete delivery and byte bounds

The local transport consumes the complete fact packet and image-bearing guard,
reconstructs the full body and validates packet/body/guard/image digests before
returning a `tplaiter.dev/context-root-delivery-receipt/v2` receipt. Its six keys
are apiVersion, bodySHA256, packetSHA256, guardSHA256, imagesSHA256 and fileCount.
The output reserve is measured from the actual serialized receipt, never a fixed
allowance. The public result still includes the entire body and all images.

Delivery bodySHA256 covers ordinary typed v2 body serialization; packetSHA256
covers ordinary typed restored C03 serialization; imagesSHA256 covers the complete
typed file array. logicalSHA256 separately uses canonical C03 JSON. These are
representation integrity observations, not substitute source or authority pins.
ResponseSHA256 and output spending describe the actual receipt. The body hash
must be checked by the compiled typed decoder/serializer, not by hashing an
arbitrary differently ordered JSON substring of a canonical outer frame.

C03 logical bytes, actual C04 input plus output reserve, the plan report,
Finish-retained envelope, ROOT and outer ContextData bytes, and final CLI/MCP
frames each retain their real bounds. ContextData.bytes and ROOT bytes measure
the serialized v2 wire. The final frame includes its outer envelope, MCP ID and
summary, base64, escaping and newline. Requests remain bounded by 32768 bytes.
Insufficient complete capacity refuses wholly. No prerequisite, procedure,
image or normative guide is truncated or replaced by a bare block. A larger
legal ID or project summary can require a whole-frame refusal.

The public template's individual four selectors are exercised through normal
configured local-operator enrollment and fresh installation. A batch may exceed
the unchanged complete logical C03 ceiling and refuse. Enrollment attests captured
public bytes without claiming upstream publisher identity or organization trust.
Transparent rule composition remains the separate existing ResolveModifiers API:
explicit add/replace/remove, digest/version preconditions, ordering and tombstones.
Selection does not apply those operations automatically.
